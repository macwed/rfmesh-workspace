# Scratchpad WS-B 2026-05-15

## Note 1 -- tests/__init__.py interpretation in WS-B-002

**Ticket:** WS-B-002 "Files you may touch" lists
`packages/rfmesh-dsp/tests/__init__.py` with annotation
`(create OR no-op if WS-B-001 created it)`.

**Conflict:** rfmesh-sdr already ships an empty
`packages/rfmesh-sdr/tests/__init__.py`. When rfmesh-dsp adds a parallel
empty `tests/__init__.py`, `uv run mypy packages/` (the just-verify
`type` recipe) fails:

> error: Duplicate module named "tests" (also at
> "packages/rfmesh-dsp/tests/__init__.py")

mypy resolves both `tests/__init__.py` files to the top-level module name
`tests`, and refuses the collision. The workspace `pyproject.toml`
`[tool.mypy]` block does not set `explicit_package_bases`, a per-package
`mypy_path`, or namespace-package handling that would disambiguate.

**Resolution chosen for this ticket:** I interpreted the ticket's
"create OR no-op" clause permissively and did **not** add
`packages/rfmesh-dsp/tests/__init__.py`. pytest's rootdir-based discovery
still picks up every test file under `packages/rfmesh-dsp/tests/`, and
`just verify` passes. The conftest fixture `golden_dir` lives in
`packages/rfmesh-dsp/tests/conftest.py` and is consumed by both test
modules without requiring an `__init__.py`.

**Decision the lead may want to take:**

1. Confirm "no-op when verify would otherwise fail" is the intended
   interpretation, and update WS-B-001's ticket (which also lists the
   same file) to match.
2. Or pick a workspace-level mypy resolution -- e.g. add
   `explicit_package_bases = true` and an empty `mypy_path`, or drop the
   `tests/__init__.py` from rfmesh-sdr too -- and re-confirm the file is
   expected in every workstream's `tests/`.

I did not modify the workspace `pyproject.toml` or any rfmesh-sdr file:
both are out of scope for WS-B-002 ("Files you may NOT touch").

**Status:** Provisionally produced WS-B-002 diff with no
`tests/__init__.py` under rfmesh-dsp. `just verify` is clean. Mark this
note resolved once the lead picks an option.
